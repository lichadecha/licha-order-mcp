# SKILL.md 版本史

> 只做留档，不是现行规则。旧版本里的说法很多已被后来的版本取代，点单时以 [SKILL.md](../SKILL.md) 为准。

- v1.10.0（2026-11-26）配合规格 v1.18。开头写明官方与品牌名的几种写法；默认店不对顾客提；卖没卖完以点单卡片为准（列表不保证当天状态），对顾客说「卖完了」不说「估清」；找店没找到时照提示直说那个城市还没有店；「以门店收银台为准」改为「以小程序里显示的为准」（顾客在小程序付款）；统一说「李茶的茶小程序」；营业时间示例不写具体钟点。
- v1.9.0（2026-11-26）配合规格 v1.17。装好后的第一句话按工具列表二选一，不再让顾客猜「开没开下单」，不反问要不要点单；安装和报错过程不讲给顾客，列出不说的词；去掉「让顾客装地图工具」；「用这张券」不再把没表态算同意；超时话术的分钟数照待确认单；固定话术不受「不超过三句」限制；提交那一步出错不建议去小程序重下；面向顾客的「这台电脑」改为「这台设备」或「我这边」；版本史移出说明书。
- v1.8.0（2026-11-24）配合规格 v1.16。实付为零时请顾客核对订单状态，临期积分按已知日期说明。替顾客挑券后等待三项确认，会员信息有变化时重新收码。
- v1.7.2（2026-11-24）按规格 v1.15.1 统一绑定条件。单独查本人的订单、积分或等级也可绑定。积分只查，兑换去李茶小程序积分商城。
- v1.7.1（2026-11-24）补充验证短信暂时停发时的转达方式（配合规格 v1.15）。
- v1.7.0（2026-11-24）：默认组单会替用户挑一张券并指定。多张时念出每张能省多少，询问用哪张或不用券。用户说随便就用挑好的那张。读回核对这张券，差额跟念单时说的预计实付比（配合规格 v1.14）。
- v1.6.0（2026-11-24）：新增「问积分、会员等级」（配合规格 v1.13 的 my_member_info）；积分只引导去小程序积分商城兑换。
- v1.5.1（2026-11-24）：明确「没有会员」时只引导到小程序用自己的手机号注册，AI 不代注册；注册前照常可浏览、算价。
- v1.5.0（2026-11-24）：新增「问配料、热量、酒精」——只依据点单卡片的品牌描述与标签，没写就说没提供；含酒精念单时提醒；多号绑定不问号码是谁的（配合规格 v1.12.3）。
- v1.4.1（2026-11-24）：第十二次独立审查——速查表补多号切换免收码、下单链路写明三样确认与大单二次确认、催单精简时保留每行杯数（配合规格 v1.12.2）。
- v1.4.0（2026-11-24）：一台电脑可绑几个号、替朋友点不用每次收码（配合规格 v1.12 BND-15）；下单铁律——数量（含总杯数）、优惠、金额三样必须得到用户明确确认才可下单，催促时也不许省；大单（10 杯或 300 元及以上）再确认一次；念单固定带【一共】【优惠】；替别人点要说清下在谁名下（配合服务端规格 v1.12.1：不限单量、不限金额）。
- v1.3.1（2026-11-23）：第十一次独立审查指出的话术问题——「可能已发出」那句的等待时长照工具原话说，不写死一分钟；「为什么要验证码」不再承诺以后永远不用收；「再来一单」只念订单里有的商品和数量，门店和规格做法要问；补上「回复认不出」与「今天的验证短信发完了」两种情形（配合服务端规格 v1.11.2）。
- v1.3.0（2026-11-23）：绑定改为两步——报手机号后收短信验证码、报出验证码才绑定（配合服务端规格 v1.11）；只支持手机号；新增「为什么要验证码」的说法；新增「再来一单」：从最近订单里取上一单重新组单，照常念单确认。
- v1.2.1（2026-11-23）：第十次独立审查指出的话术问题——指定券的读回只说 note 里有的事实（抵扣金额读不到就不念；只有门店活动、没用券时不说成用了别的券；同时用了两张都要说）；新增「用的是那张但实付比念单时高」的说法；没有 `ref` 的券说明暂时没法指定（配合规格 v1.10.1）。
- v1.2.0（2026-11-23）：用户可以指定用哪张券（配合服务端规格 v1.10）。问「我有什么券」先组单再念可用券；点名哪张就带 `couponChoice: "specific"` 和那张的 `ref` 重新组单，念「这单用你的『X』」；读回核对用的是不是那张，没照办时如实说明、给出接受付款或到小程序取消两条路，不重下。
- v1.1.1（2026-11-23）：第九次独立审查指出的话术冲突——选了不用券时念单要说「不用券」，催单时的四样底线加上「不用券」；门店系统没照办且应付为 0 时不说「去付款」；读回失败、结果未知两种情形提醒顺便核对有没有用券。
- v1.1.0（2026-11-23）：用户可以选「这单不用券」（配合服务端规格 v1.9）。用户说不用券就带 `couponChoice: "none"` 重新组单、念「这单按你说的不用券」；下单后按读回核对有没有照办，门店系统没照办时如实说明、给出接受付款或到小程序取消两条路，不重下。
- v1.0.1（2026-11-22）：对用户说的会员尾号统一为他自己报的号的尾号（配合服务端规格 v1.3 绑定出参新增的 `member`、`previousMember`；此前绑定时念内部会员编号尾号、念单时念手机尾号，用户会听到两个不同尾号）；绑定成功按出参三选一；念单合计带「以门店收银台为准」；下单成功说「应付」不说「实收」（还没付款）；加料是可选项，用户没提不追问；工具连续失败两次的收尾。来源：模拟环境里一位只读本说明书的 AI 顾客从头点单的走查；第二次走查后又补三处：要下单时直接 prepare_order 不先单独算价、写清未绑定是在 prepare_order 时发现、念单时门店限制（如只开堂食）带在门店后面；复述金额照待确认单写、最多两位小数（配合服务端规格 v1.6）；查订单时没标明归属的订单不展示、只提示去小程序看（配合 v1.7）。
- v1.0.0（2026-11）：服务改为「品牌方服务器 + 顾客端薄壳」形态，顾客电脑不再持有任何商户钥匙。话术随之变化：会员绑定按设备保留一段时间，念单必须说出下到哪位会员名下；刚下过单再组单时先问是不是要再下一单；实付为 0、读回失败、结果未知各有固定话术；优惠区分「确定是券」与「看不出是不是券」；用户想自己选券时指路到小程序；「为什么要手机号」改为如实说明用途；门店不再写死数量。此前的版本史见旧版仓库 v0.5.3 的同名文件。
